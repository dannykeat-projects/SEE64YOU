# SEE64YOU v0.2.0-alpha.2 — manual-save 8TML Editor preview

This prerelease updates the offline C64 Ultimate Editor. Periodic autosave is removed: **save manually with Ctrl+S or File → Save**. Save As, undo/redo, unsaved-change prompts and recovery of existing snapshots remain. Help now clears correctly when returning to a short document; the inactive PUB menu is removed. A saved document asks **Exit to BASIC? Y/N** before leaving; only Y exits. Dirty documents retain Save / Discard / Cancel.

The optional Publisher now accepts explicit HTTP ports such as `:8080`. The PHP service limits request bodies to 128 KiB and outstanding authentication challenges to 128, with expiry cleanup. Native source validation rejects conflicting version declarations. Earlier release assets remain unchanged.

## Installation

Back up documents and configuration first. Choose one complete eleven-file package:

- `SEE64YOU-v0.2.0-alpha.2-c64u-sd.zip`: `/sd/SEE64YOU/`.
- `SEE64YOU-v0.2.0-alpha.2-c64u-usb0.zip`: `/Usb0/SEE64YOU/`, **only when the actual mount is exactly `/Usb0/`**. `/USB1/` and other mounts require a complete build with the matching `STORAGE_ROOT`; renaming folders cannot change embedded paths. USB hardware acceptance remains incomplete, and USB FTP corruption has been reproduced on the tested firmware. Exact readback is essential; the SD package is the tested installation path.
- `SEE64YOU-v0.2.0-alpha.2-php-site.zip`: optional independent PHP 8.1+ publishing service.

Verify ZIPs using release `SHA256SUMS`. Each client bundle includes `BUILD.json`, per-file checksums and this guide. Copy all eleven matching files from `SEE64YOU` to the selected mount; never mix packages. Preserve existing documents, configuration and recovery files.

In **Ultimate menu → F2 Settings → C64 and Cartridge Settings**, enable **Command Interface**, **RAM Expansion Unit**, and **REU Size: 16 MB**. Launch **SEE64YOU.PRG**, not internal S64EDIT.PRG. Offline editing needs no website or publishing credentials.

## Editing and saving

New source contains an editable `8tml: 1` / `title: Untitled` header. Keep delimiters and version valid. Ctrl+S with basename `FIRST` saves `FIRST.8tml`; wait for **File saved**. Ctrl+Shift+S saves under another name. Ctrl+O opens source; native alternatives are Commodore+F3 Open, Commodore+F5 Save and Commodore+F7 Save As. F8 shows Help. Ctrl+Z undoes and Ctrl+Shift+Z redoes. Physical modifier-key acceptance remains pending.

Files preserve complete literal source, unknown metadata and markup, using ASCII and LF. CR/CRLF reads normalize to LF; maximum complete source is 61,440 bytes. No historical `.s64` import or conversion is provided. Generated HTML is not the editing source.

RUN/STOP asks for confirmation on saved documents, or Save / Discard / Cancel when dirty. Existing recovery snapshots may show **Recover snapshot? Y/N**; failed reads preserve them. There are **no automatic background saves of new edits**. Keep independent backups and retained `.tmp` files after failed disk operations.

## Optional publishing and limitations

Publisher and Settings launch separately as S64PUB.PRG and S64CFG.PRG. For a disposable PHP site, follow start.php/setup.php and pair a dedicated key through HTTPS pair.php. Settings uses the site's `http://` folder URL, optionally including a decimal port 1–65535, without api.php. **Enable plain-HTTP consent explicitly**, save, and require **SETTINGS SAVED AND VERIFIED**. HMAC authenticates requests but does not encrypt content; pairing must use HTTPS. Native direct transport does not silently downgrade HTTPS.

Publisher loads `.8tml`, publishes source and downloads to a new local filename. Browser still reads the historical SEE64YOU protocol; it is not an 8TML reader. PHP HTML rendering supports the existing escaped subset, not the full language. This is an **Editor-focused alpha**, not complete-product or beta acceptance. No T8WN/VVV interoperability is claimed.

## Validation

Release gates include PHP/HTTP authentication and source regression tests, host/REU source/storage/failure tests, reference validation, cc65/VICE checks, both complete storage-root builds, memory guards and manifests. Release SD payload hashes must match a successful REST-assisted real-C64U Editor/storage receipt with complete file and machine-state restoration.

REST-assisted hardware checks are separate from physical keyboard feel, modifier Open, cold-power restart, uncontrolled interruption, USB-only storage and Publisher network acceptance. Those remain pending. The exhaustive unknown-markup reference fixture deliberately emits one emphasis warning; actual hardware output must have zero errors and warnings. See [validation procedures](../LOCAL_TESTING.md) and [the work queue](../../todo.md).
