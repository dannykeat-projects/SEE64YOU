# SEE64YOU v0.2.0-alpha.1 — 8TML Editor preview

This alpha focuses on the offline C64 Ultimate Editor. It creates and edits **8TML 1 draft** source; it does not import or convert historical `.s64` documents. Back up your files and configuration before replacing an installation. Physical-keyboard, cold-power, interruption and USB-only hardware acceptance remain incomplete.

## Choose one complete client package

- `SEE64YOU-v0.2.0-alpha.1-c64u-sd.zip` uses `/sd/SEE64YOU/`.
- `SEE64YOU-v0.2.0-alpha.1-c64u-usb0.zip` uses `/Usb0/SEE64YOU/`. Choose it **only if the actual Ultimate mount is exactly `/Usb0/`**. Another mount needs a complete build with its own `STORAGE_ROOT`; renaming the folder does not change embedded paths.
- `SEE64YOU-v0.2.0-alpha.1-php-site.zip` is a separate optional publishing service, requiring PHP 8.1+.
- Release `SHA256SUMS` verifies the ZIPs. Client bundles include `BUILD.json`, file checksums and installation guidance.

In **Ultimate menu → F2 Settings → C64 and Cartridge Settings**, set **Command Interface: Enabled**, **RAM Expansion Unit: Enabled** and **REU Size: 16 MB**. Copy all **eleven matching files** from the chosen bundle's `SEE64YOU` folder to its selected mount. Keep internal assets beside the programs; never mix SD/USB bundles or releases. Historical `v0.1.0-alpha.1` assets remain separate.

Launch **`SEE64YOU.PRG`** to edit. Do not launch internal `S64EDIT.PRG` directly. No website, publishing key or Settings setup is needed for offline editing.

## First offline document

1. Launch Editor. If a prerequisite screen appears after changing Ultimate settings, press **R** to recheck.
2. A new document contains an editable header with `8tml: 1` and `title: Untitled`; typing begins in the empty body below it. Keep the version/header delimiters valid. **Ctrl+N** starts another document after resolving unsaved work.
3. Type a short test. **Ctrl+S**, basename `FIRST`, then Return saves `FIRST.8tml` in the selected package folder. Wait for **File saved**. **Ctrl+Shift+S** saves under another name; an existing file requires explicit overwrite confirmation.
4. **Ctrl+O** opens `FIRST.8tml`. Edit it, save, reopen and compare the result. The corresponding native alternatives are **Commodore+F3** Open, **Commodore+F5** Save and **Commodore+F7** Save As. **F8** shows the key reference. These mappings exist in code; automated injection does not certify physical-keyboard behaviour.
5. **Ctrl+Z** undoes an edit; **Ctrl+Shift+Z** redoes it. Source formatting inserts markup rather than rendering a web page. Header fields and unknown markup remain literal editable text.
6. **RUN/STOP** exits to BASIC. Unsaved changes offer **S Save / D Discard / STOP Cancel**. On a later launch, **Recover autosave? Y/N** offers a retained recovery snapshot; save recovered work to a named source file before continuing experiments. Recovery is not a backup or a power-loss guarantee.

Saved files are ordinary **ASCII with LF line endings**. Reads normalize CR/CRLF to LF. The complete header and body share the existing **61,440-byte** limit. Unsupported bytes and invalid headers are rejected; Save As adds `.8tml` to a basename and refuses another explicit extension. Keep independent copies of important documents and any retained `.tmp` recovery file after a failed save.

## Optional publishing

Editor and Publisher launch independently. `S64PUB.PRG` loads `.8tml`, publishes through the matching PHP service, opens remote source and downloads to a **new** local filename. Reopen that downloaded file in Editor. Service identity and publication state stay outside the document header; unedited service date/order survive source updates.

For a new disposable site, upload the separate PHP package, follow `start.php`/`setup.php`, and provision a dedicated key through **HTTPS `pair.php`**. In `S64CFG.PRG`, enter the site's **`http://` folder URL**, without `api.php`, and the dedicated key. **Explicitly enable plain-HTTP consent**, save, and require **SETTINGS SAVED AND VERIFIED**. The current native direct transport uses **port 80 and rejects explicit port suffixes**, including `:8080`. HMAC authenticates requests but does not encrypt content; HTTPS pairing is never silently downgraded.

In Publisher, **L** loads source, **2** tests the key, **T** selects page/post, **4** selects draft/published and **3** saves, asking for the remote slug on the first local upload. **6/7** open a remote page/post; **D** saves a new local copy without overwriting existing source.

`S64WEB.PRG` remains an optional historical SEE64YOU-site reader, **not an 8TML reader**. The PHP HTML renderer supports the existing safe subset, not the complete 8TML language. No T8WN/VVV publishing interoperability is claimed.

## Validation and remaining gates

Release preparation includes host source/storage and failure tests, full-capacity Publisher/PHP round trips, supplied-reference validation, cc65/PETSCII and VICE checks, both storage-root builds, memory guards and package manifests. On 22 October 2026, the current SD Editor build passed REST-assisted real-C64U creation/save, recovery reopen/edit/resave and native DOS/source/fault-recovery checks. Actual output passed the reference validator with zero errors/warnings. All 38 original files, full configuration, both DOS contexts and machine baseline were restored and verified. Release SD payload hashes must match that tested package.

Physical-keyboard usability/modifier Open, cold restart, uncontrolled interruption, actual USB-only hardware and the new Publisher's hardware acceptance remain separate gates unless the release report explicitly records them passing.
