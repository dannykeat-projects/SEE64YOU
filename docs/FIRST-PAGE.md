# From setup to your first page or post

Keep your website's `start.php` open in a browser for the step-by-step wizard. It links to website setup and HTTPS pairing, and tells you exactly which C64U keys to press. Settings points back to the browser guide. This checklist covers the independent publishing workflow and offers an optional check using the separate C64U browser.

1. **Prepare the C64U.** Back up existing SD files and configuration. Copy all eleven files from the matching independent package into `/sd/SEE64YOU/`. Enable Ultimate Command Interface and, in Ultimate menu â†’ C64 and Cartridge Settings, RAM Expansion Unit = Enabled and REU Size = 16 MB. Connect the C64U to your network. Editor's prerequisite screen offers R to recheck after changes.
2. **Create the website.** Upload the standalone PHP site package to PHP 8.1+ hosting. For a fresh site, create an empty `ENABLE_SETUP` marker and open `setup.php` in your browser. Choose title/theme and a publishing password (at least eight characters); successful setup removes the marker. Preserve an existing configured site. For local development use a PC address reachable from the C64U; `localhost` on the C64U cannot reach your PC.
3. **Pair securely.** Open `pair.php` over HTTPS and enter the browser publishing password. Save the displayed 64 hexadecimal key characters as `/sd/SEE64YOU/SEE64KEY.TXT`, or type them in Settings. Keep the key private and remove the import file after use. The C64U never needs your normal site password.
4. **Save Settings.** Launch `S64CFG.PRG`. Its wizard opens when site/key settings are missing; otherwise W runs it again. Step 1: 1 enters the site-folder URL (no `api.php`), Return, N. Step 2: 1 imports the key, or 2 types it, then N. Step 3: direct firmware-1.1 publishing uses an explicit `http://` URL and unencrypted document text; 1 then Y gives consent only if acceptable. HTTPS is never downgraded; use Advanced for a separately configured relay/other transport. S saves. Wait for `SETTINGS SAVED AND VERIFIED`, then Return to BASIC. Reopen Settings to check persistence; STOP cancels unchanged. B goes back, W opens Basic, STOP cancels setup. Editing offline is always available separately.
5. **Write a source file.** Launch `SEE64YOU.PRG`. Ctrl+N starts a new document after resolving any unsaved/recovered content. Type your text. Ctrl+S, a new basename such as `FIRST` (the `.s64` extension is added automatically), Return saves under `/sd/SEE64YOU/` by default and supplies the initial title/slug from the filename. Wait for saving to finish. RUN/STOP returns to BASIC; a dirty document offers S Save / D Discard / STOP Cancel. Keep your `.s64` backed up.
6. **Publish.** Launch `S64PUB.PRG` fresh. L, `FIRST.S64`, Return loads your source. Check displayed title/slug. Press 2 and wait for connection success. T toggles page/post: change it only if needed. 4 toggles draft/published: select published for public visibility. Press 3 once and wait for `Document published`. RUN/STOP returns to BASIC. Changing type/state in Publisher does not rewrite the original `.s64`; recheck these after later loads.
7. **Confirm and edit later.** Open your website: pages appear in navigation, posts in the post archive. Follow the link and check exact text. To update with current remote metadata, launch Publisher, 2 connect, 6 pages or 7 posts, Space Next, O open, Y if asked, then wait for `Remote document opened`. Only then press D and save to a NEW filename (for example `FIRST2`; `.s64` is added automatically). Existing download files are refused. Exit; reopen/edit/save that file in Editor; then fresh Publisher loads it and updates the same slug/type. Optionally launch `S64WEB.PRG`, press O to enter the public `http://` See64You site URL, then use Up/Down and Return to navigate the published content. This reader cannot open HTTPS or arbitrary HTML sites.

Loading, Saving, Connecting and Publishing messages mean the operation is working. Wait for the result before extra keys. On failure, keep the source, correct the reported problem and retry. A saved configuration is not proof of a successful connection; Publisher tests it. A draft is not publicly visible. Complete temporary files may be recoverable after interrupted replacement; copy them before retrying.

Three functional publishing round trips, the independent C64U browser and the SD-folder migration have passed bounded real-C64U tests. The Settings wizard also passes software/VICE and real-C64U first-entry/import/consent/verified-save/relaunch/cancel/authentication checks using remote plain keys. A complete first-time-user run with physical wizard key input remains unverified. USB and uncontrolled physical storage/power interruption tests are deferred. See LOCAL_TESTING.md for exact scope.
