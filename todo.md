# SEE64YOU work queue

This is the live queue for the local-model experiment. [Product scope](docs/PRODUCT.md) defines the supported programs. [Development and acceptance](docs/LOCAL_TESTING.md) describes the commands and hardware procedures.

## Baseline and evidence

Alpha.8 is the released ten-file package. Ordinary sources live in `SEE64YOU/docs/`. The experiment adds an aligned REU read window and an 80-character Publisher status display. See the [release](https://github.com/dannykeat-projects/SEE64YOU/releases/tag/v0.2.0-alpha.8) and the [pre-audit evidence ledger at 53d006e](https://github.com/dannykeat-projects/SEE64YOU/blob/53d006e26e734e1ad7b2e2b8beec680b344429af/todo.md) for historical commands, hashes, regressions and hardware receipts.

Recorded candidate evidence includes 98 host groups, forced SD/USB1 shipping builds, and 24 REST-assisted SD hardware gates on firmware 1.2.1 at f96e40b. The latter covered 8SS/TXT public readback, replacement/cancellation and size rejection. The aligned window cut host REU loads for a 60,000-byte long-line navigation case from 1,345,687 to 55,486. Physical post-delete latency and the reported 8TML upload failure remain open. USB1 Publisher had 1,087 bytes free against the 1,024-byte minimum. One ordinary 8TML document did publish through the installed release package on the SD card on 25 Nov 2026 (installed `S64PUB.PRG` 44,863 bytes sha a9a26641..., `SEE64YOU.PRG` 47,129 bytes sha 50f1c1a5...): local `docs/notes.8tml` 200 bytes sha 0af7f0f0262e058e10071194a0a09ec134cc0f82476f8384301acf7229777430 produced **PUBLISHED** with `http://t8wn.com/@keato/notes.8tml`, the authenticated list gained only `notes.8tml`, and the URL reads back HTTP 200 with 216 bytes because the site inserts its own `style: plot.8ss` header line, which Publisher reports as a server warning; leaving that result screen with RUN/STOP showed **PUBLISH CANCELLED** and wrote nothing. The truncated server message in the reported failure did not appear on these screens, so its cause stays open. Receipts `client/build/acceptance-20261125-notes` and `client/build/acceptance-20261125-notes-final3`; ledger at ea3d44e.

## Code quality audit and implementation plan

Reviewed source at `53d006e` on `codex/local-model-experiment`, 25 November 2026. The review inventoried all 559 tracked paths and followed representative production, failure, test and packaging paths across each subsystem. The findings below distinguish code behavior, host measurements and outstanding device checks. Start with recovery and establish the performance baseline before changing the model. Keep each change independently measurable and revertible.

### 1. Protect source and recovery

- [ ] **Fix cancellation at startup first.** In [offer_recovery](client/src/main.c), a false answer to “Recover snapshot?” calls the deletion routine and then reports “Recovery discarded” regardless of its result. [s64_ui_prompt_yes_no](client/src/ui.c) returns false for both N and RUN/STOP. A user trying to back out can therefore delete the recovery copy. Give this prompt distinct recover, keep and explicit discard outcomes. Check the DOS result before reporting deletion. Test each key, failed deletion, failed read and relaunch with each snapshot format. Review the other callers of `clear_recovery_snapshot` for misleading success after cleanup failure.
- [ ] **Make replacement failures actionable.** [write_document_file](client/src/storage/local.c) can promote the new source successfully and then return an I/O error deleting the backup. It also ignores the rollback rename result if promotion fails. Distinguish “saved, backup retained” from “replacement failed, recover from .bak/.tmp”. Exercise both failures, including a second Save and reopening the original name. Assert exact bytes and dirty state for each outcome. Exercise oversized/invalid Open, midstream read failure, and partial paste/undo at full history capacity. Preserve collision refusal and the sticky REU fault.
- [ ] **Keep startup and exit recoverable.** Trace launcher recovery, platform session journal, BASIC-return assembly and DOS contexts as one lifecycle. Extend existing fault tests at ACTIVE persistence, apply, restore, verify and CLEAN persistence. Confirm a failed restore leaves a recoverable record. Check exact idle BASIC, colours, IRQ, turbo, mount and file hashes after a matched-package run. Keep historical managed Editor fit failures tracked separately from the independent shipping target.

### 2. Measure and reduce end-to-end work

Host counters reproduced with `python3 tools/test_editor_performance.py` at 60,000 source bytes. Counts below are REU load calls per operation. They exclude shipping overlays, display, DOS and physical input.

| Operation | One logical line | Lines of 40 columns |
| --- | ---: | ---: |
| End of line at midpoint | 55,486 | 39 |
| First insert at midpoint with gap at EOF | 1,244 | 508 |
| Paste 1,024 bytes at midpoint | 28,634 | 1,102 |
| Two Save codec invocations | 3,752 | 3,752 |

- [ ] **Separate navigation, gap movement and drawing.** In [editor.c](client/src/editor.c), trace line-start/end scans, visibility and pointer mapping. Instrument [buffer_reu.c](client/src/buffer_reu.c) gap moves and [ui.c](client/src/ui.c) row paints and overlay switches separately. Compare wrap on/off, post-delete/reopen, first edit and sustained input at 1,024/16,384/60,000 bytes. Start with reuse of a known row/line position for backward clicks or wrap boundaries. Verify position, selection, horizontal scrolling, reflow and redraw against the existing full path. Record median, worst case and sample count on physical C64U with identical firmware, turbo and package inputs.
- [ ] **Batch the path the counters justify.** Paste reads clipboard chunks but calls `s64_buffer_insert` per byte. History swaps and gap relocation also have distinct transfer costs. Prototype one bounded bulk insertion using existing scratch space, then compare 64/256/1,024-byte pastes. Gate on fewer transfers, correct partial-failure state, exact saved bytes, undo/redo and both roots' fit. Keep large-document first-key latency as a separate measurement.
- [ ] **Measure Save and Open through DOS.** The two calls to `s64_document_write_wire` in `write_document_file` read 240,128 bytes in the host 60,000-byte Save fixture. Compare a narrower validation pass plus streaming write against current preflight. Test failing transfers in both phases, temp conflicts and rollback before accepting a change. For Open, the source-loading fixture already validates normalized bytes up to 61,440. Compare shipping elapsed time on matched SD packages before attributing gains to batching.

### 3. Make publishing bounded and diagnosable

- [ ] **Localize 8TML upload failures.** Use the independent-server gate above and the existing round-trip fixtures. [publish](client/src/publisher/standard_main.c) does status and authenticated list, then [s64_standard_put](client/src/publisher/standard_transport.c) does another status, challenge and PUT. Time each exchange and source pass. Keep the final size check and fresh challenge unless changed-limit and independent-caller tests demonstrate an equivalent safeguard. Do not retry ambiguous writes.
  - **Recorded 25 Nov 2026:** the create path on the *installed release* package passed end to end: PUBLISHED plus the public URL, authenticated-list delta of exactly `notes.8tml`, HTTP 200 readback whose only difference from the local source is the site's inserted `style: plot.8ss` line, and restoration verified after the run (IRQ `$0314` = `31ea`, turbo 0, colours 254/246/14, drives and configs byte-identical, scratch byte 827 back to `00`, empty responsive BASIC). The reported truncated message did not reproduce in those screens; 8TML replace/cancel on the candidate package and physical keyboard/mouse remain unverified.
- [ ] **Make receive deadlines predictable.** The standard transport stops after 512 idle reads or 4,096 polls. Elapsed time depends on firmware and data fragmentation. Evaluate the existing [deadline proposal in PR 75](https://github.com/dannykeat-projects/SEE64YOU/pull/75) against this branch. Exercise slow first byte, steady fragments, stalled transfer, clock rollover and late reply after PUT. Retain a bounded total wait, socket cleanup and uncertainty semantics. Measure both memory maps before adopting it.
- [ ] **Separate result information within the fit budget.** `reply_line` stores error, message and warning in one field, so arrival order determines what survives. HTTP status stays internal. The three-row display in [standard_display.c](client/src/publisher/standard_display.c) already retains 80 characters. Design a compact outcome with operation, HTTP code, brief server reason and next action. Test reversed field order, long-to-short messages, warnings and uncertain outcomes on the 40×25 grid. USB1 previously had just 63 bytes above the Publisher guard. Measure before adding persistent fields.
- [ ] **Stop unnecessary directory reads.** [s64_local_pick](client/src/publisher/local_picker.c) reads a page at the top of every input iteration. An irrelevant key or Previous on page one reopens and scans the same directory. Handle keys against the displayed page and fetch only on entry or a real page change. Then bound cancellation/draining in [dos_dir.c](client/src/platform/dos_dir.c) and UCI. Count DOS operations in tests for ignored keys, empty pages, scan limit, mid-read STOP and successful next operation. Remote paging also reissues an authenticated list per page. Measure that separately and retain fresh existence checks at confirmation.

### Audit verification

The audit reran source/storage tests, source-loading and Editor performance fixtures, REU clipboard/history/window checks, standard transport and Publisher round-trip tests (RAM and simulated REU), result-screen tests, 16 relay tests, overlay fit helper and six release-packager tests. Historical package checksums matched. GCC 14.2.0 and Python 3.12.14 were used. Address/undefined sanitizer runs for the round-trip and renderer passed with leak detection disabled after LeakSanitizer reported an incompatible traced environment.

The full host script stopped at PHP syntax checks because PHP CLI was unavailable. Native shipping builds and VICE were unverified here (cc65 and VICE absent). No physical device, independent publication or new shipping fit claim forms part of this audit. Apply the [release acceptance gates](#outstanding-release-acceptance) to implementation commits and retain exact artifacts, hashes and restoration evidence.
